# DeepSeek 用量 · 任意时间段（Chrome 扩展）v3.0.0

让 DeepSeek 开放平台「用量」页（`platform.deepseek.com/usage`）支持**任意时间跨度**查询：
把大区间自动拆成官方后端允许的分片拉取、在浏览器本地合并，再交给官方界面原生渲染；
附带面板汇总（费用 / 请求数 / Tokens / 按天明细）与 CSV 导出。

> **全新实现**。旧版出问题的根因是：官网 2026-10 起在用量接口里新增了 `functions` /
> `function_series` 字段（网页搜索 / 抓取工具计费），而官方前端对 `function_series`
> 是**无条件解引用**——旧版合并时把不认识的新字段丢掉，页面一拿到合并数据就报
> `Failed to load usage data`。v3 的合并是「结构无关」的：官方加什么字段都原样保留，
> 并对已知的崩溃点做了兜底（详见「稳定性设计」）。

---

## 一、安装（约 1 分钟）

1. 打开 `chrome://extensions`，右上角打开「开发者模式」；
2. 「加载已解压的扩展程序」→ 选择本文件夹（包含 `manifest.json` 和 `content.js` 的目录）；
3. 打开 / 刷新 `https://platform.deepseek.com/usage`；
4. 筛选栏「Export」旁出现 **「任意时间段」** 按钮即安装成功（找不到按钮时它会自动变成右下角悬浮按钮）。

> 更新版本：用新文件覆盖同名文件后，在 `chrome://extensions` 点扩展卡片上的 **刷新（↻）**，再硬刷新用量页（Ctrl+Shift+R）。
> 卸载：在 `chrome://extensions` 移除即可，无任何残留权限。

## 二、使用

- **应用并查询**：在「任意时间段」面板里选预设（近 30 / 90 / 180 天、近 1 年、全部）或手动输入起止日期 →
  点「应用并查询」。面板立刻显示该区间的 **总费用 / API 请求数 / Tokens / 按天明细表**。
- **同步官方图表**：点此按钮会刷新页面，官方界面的 KPI 卡片、图表、明细表就会渲染该区间
  （官方「Time」筛选的显示文字仍是预设名，数据是增强区间——面板按钮上会显示真实生效的区间）。
- **导出 CSV**：按「日期 × API Key × 模型/功能」的完整明细，指标列（费用、各类 Token、请求数、
  工具调用等）**按数据动态扩展**——官方新增任何指标都会自动出现在 CSV 里。带 BOM，Excel 直接打开不乱码。
- **API Key 过滤**：面板下拉只影响面板表格和 CSV（官方自己的「API Key」筛选照常可用，两者独立）。
- **全部**：自动向前探测你最早的用量日期（按 31 天窗口回扫，最多约 3 年），再把区间起点定到那天。
- **恢复原生**：一键回到官方默认行为（单次最多 31 天）。
- 如果你在官方「Time」里手动换了时间筛选，增强会**自动让位**给原生筛选（重新点「任意时间段」即可再启用）。

## 三、稳定性设计（为什么它不会“轻轻一改就坏”）

1. **结构无关合并**：分片响应整体做深度合并——未知字段原样保留；`series` / `function_series` /
   `data` 等对象数组按「身份签名」（除 `buckets` 外的字段集合）归并；桶数组按 `time` 对齐拼接；
   `models` / `functions` 等标量数组取并集。官方新增字段、新增指标、新增维度都自动兼容。
2. **已知崩溃点兜底**：只要对象里有 `series` 数组而缺 `function_series`，自动补空数组——
   这正是 2026-10 那次官网改动导致整页报错的崩溃点。
3. **逐日补零**：把每个 series 的桶补齐到完整日网格（形状与原桶一致、数值为 0），
   图表 X 轴覆盖整个区间，稀疏数据不丢天、不错位。
4. **失败必回退，绝不硬塞**：任何分片拉取 / 合并 / 校验失败（超时、非 JSON、登录失效、
   响应结构变化导致找不到数据节点……），都**原样放行页面自己的原生请求**，页面照常工作
   （最多回到 31 天限制）。宁可少增强，绝不出错数据、绝不触发官网的登出逻辑。
5. **请求识别宽松**：按路径里 `usage/by_api_key/<指标>` + `start/end` 参数识别，不依赖完整 URL
   常量；指标名变化（cost / amount 之外新增）也能拦截。
6. **鉴权双重保障**：优先复用页面请求自带的 `Authorization` 与设备头（跟随官网登录态存储变化）；
   失效时自动扫描本地 token 候选重试；仍失败则回退原生。
7. **分片按算术切分**：分片边界直接由目标区间按 31 天步长切出，与官网“按天对齐（时区零点）、
   单次 ≤31 个按天桶”的校验规则天然一致；每个分片独立重试 2 次、3 路并发、60s 超时。
8. **UI 零耦合**：按钮 / 面板在 Shadow DOM 里自绘，不依赖官网 CSS 类名、不碰 React 内部；
   找不到注入锚点就退化为悬浮按钮；UI 任何异常都不影响页面。
9. **无额外权限**：Manifest 里没有 `permissions`，只在 `platform.deepseek.com` 上注入内容脚本；
   所有请求都是只读的用量查询。

## 四、故障排查

- **按钮没出现**：`chrome://extensions` 确认扩展已启用 → 硬刷新用量页（Ctrl+Shift+R）。
- **点「应用并查询」提示拉取失败**：面板会显示原因。先确认已登录开放平台；
  网络问题可重试；若提示「缺少数据节点」说明官网响应结构大改（见下）。
- **官方图表没变化**：点「同步官方图表」（= 刷新页面）。
- **数据看着像没变**：若账号用量集中在最近 30 天内，长区间和 30 天的数字本来就接近；
  以面板按钮上显示的区间与按天明细为准。
- **官网又改格式了怎么办**：本扩展遇到未知结构会自动回退原生、不影响页面；
  面板的汇总/CSV 仍可独立使用。把控制台里 `[DeepSeek用量增强]` 开头的告警发给维护者即可快速适配。
- **调试入口**：控制台执行 `__dsu.state()` / `__dsu.last()` / `__dsu.summarize()` 可查看
  当前区间、最近一次合并数据与汇总结果。

## 五、工作原理（简述）

1. 以主世界（MAIN world）内容脚本拦截 `XMLHttpRequest` 与 `fetch` 发出的用量请求；
2. 把**目标区间**拆成 ≤31 天的分片（保留原请求的其余查询参数，如 API Key 过滤），
   3 路并发拉取、逐片重试；
3. 结构无关合并 + 补零 + `function_series` 兜底，得到与官方单次响应同构的 JSON
   （`start/end/bucket/models/functions/data|series/function_series`，未知字段自动保留）；
4. 合法性校验通过后伪装成一次官方响应交还页面：`fetch` 返回合成 `Response`；
   `XMLHttpRequest` 用本地 `Blob` URL 重放（状态机、`responseType` 全部原生），
   官方组件无感渲染任意长度区间；
5. 校验不通过 → 原请求原样放行（回退原生）。

## 六、已知限制

- 官方「Time」筛选旁的文字标签仍显示原生预设名（增强区间显示在本扩展按钮与面板上）。
- 单次区间上限约 4000 天（安全阀）；「全部」向前最多探测约 3 年。
- 数据最多延迟 5 分钟（与官方一致）；时区跟随官方偏好（GMT+8 默认）。
